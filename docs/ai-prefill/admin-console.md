# Admin 文章管理与 AI 任务

本页是网页操作指南。科学提取规则仍从 [START_HERE](START_HERE.md) 进入；网页按钮调用同一份冻结指导包，不另设一套科学标准。

## 管理一篇文章

在 Admin 的文章目录打开文章，进入管理区域。可先预填后分配 Reviewer，也可对尚未编辑的已分配草稿开始第一次生成。

- **收回分配**：撤销当前 Reviewer 的编辑权限，保留同一份草稿、历史和版本。重新分配后可继续审核。旧浏览器页面不能继续保存；该文章的排队任务失效，运行任务请求停止。
- **归档并重新开始**：先输入文章编号确认。服务端把旧工作区快照、历史、布局、阅读状态、AI 记录及关联工作文件导出到固定归档目录，并验证文件哈希，再将旧工作区设为只读，创建一个新的未分配空白工作区。不会在原工作区上清空或把原版本号改回 1。
- 有待处理提交时，先完成该提交的处理。AI 正在运行时，先停止并等待确认结束，再归档。
- 源 PDF 与已发布版本保留。文章元数据仅恢复有历史证据的原值；无法证明原值的字段保留，不凭空重建。归档快照保存当时的完整文章信息。

归档按 `article_archive_root/<paper UUID>/<UTC timestamp>-<archive UUID>/` 存放。`workspace.json` 是旧工作区和历史的完整导出，`manifest.json` 记录导出文件哈希。新控制台任务的文件和关联工作资产复制到相同归档内；历史外部实验保留原路径引用，不擅自移动。

归档是保留历史，**不是永久删除**。数据库中的旧工作区、审计历史和已发布版本仍在；删除归档目录也不会删除这些记录或原任务目录。当前页面不提供不可逆的全站历史清理。后续清理应依据归档清单和数据库引用单独进行。

## 运行 AI

1. 选择文章及动作。**第一次生成**只适用于从未编辑过的空白草稿；已有数据先使用独立检查，需从零重做时先归档。
2. 选择服务器已配置的模型及推理强度、运行时间上限。第一次生成可勾选完成后自动排队独立检查，并为检查单独选择模型和强度。
3. 点击开始。任务进入持久队列；关闭浏览器不会取消任务。全站默认最多同时运行 **4 个**任务，每篇文章最多一个排队或运行任务。Admin 可调整并发上限；降低上限不会强行终止已经运行的任务。
4. 页面每 5 秒刷新状态。运行时间和阶段不等于科学完成百分比；不会伪造精确百分比。错误显示可操作的说明和错误代码，原始模型推理、账号配置和服务端凭据不发送到网页。
5. 需要中断时点击停止。运行中先显示停止中，确认受控进程退出后才释放名额。失败、超时或部分结果可创建一次新的重试，保留旧尝试；不会悄悄自动再产生费用。

第一次生成包含指导文件要求的有界自检与内部修正。候选通过技术校验且草稿身份、版本和分配未变时，自动写入该空白草稿；覆盖缺口和自检未决随报告交付，不否决草稿入库。技术上无法保存的输出保留在任务目录。写入结果仍待人工审核，不代表科学批准。

**新上下文独立检查**冻结的是点击时的现有草稿（包括人工修改），重新读取来源，在同一模型会话先完成原草稿审查，再生成有依据的修补方案。生产者自检不等于独立检查。报告展示问题项、未检查范围和检查对应的工作区版本，**不会自动修改科学数据或清除“需核对”**。检查期间发生人工修改时，报告仍只适用于原冻结版本。

独立检查需要与 PDF 哈希绑定的完整编号清单。已有历史文章若尚未注册清单，会显示 `INVENTORY_REQUIRED`，由操作者注册其真实历史清单；不能从当前 Compound 列表反向构造“完整覆盖”的分母。当前候选格式不能无损表达某些未决结构、关系或备注时，会明确阻止检查，不能偷换成旧候选。

## 操作者配置与恢复

服务器配置 `LEADTRACE_AI_TASK_WORKER_ENABLED`、`LEADTRACE_AI_TASK_ROOT`、`LEADTRACE_ARTICLE_ARCHIVE_ROOT`、`LEADTRACE_AI_TASK_PYTHON`、`LEADTRACE_AI_TASK_PRESETS` 和 `LEADTRACE_AI_TASK_INVENTORY_ROOTS`。任务与归档目录应是独立绝对路径，不与源、资产或彼此重叠，不含符号链接；任务目录位于源码 checkout 之外。只将经过源身份核实的 inventory 放入专用注册目录，避免递归扫描整个运行数据根目录。

模型列表由操作者配置 allowlist：每项包含 `id`、`label`、`adapter`（`dsh` 或 `codex`）、实际模型 ID、`efforts`、`default_effort`。网页不接受任意命令、路径或 API 地址。模型提供商账号留在服务器。选项可用只表示本机找到运行器且未被操作者禁用，不保证提供商账号权限、余额或真实调用能力。预设可填写 `unavailable_reason` 临时禁用故障通道并在网页显示原因。Admin 的 Codex 任务在启动模型前，通过同一隔离环境下的 `app-server command/exec` 执行合成 Python 命令，核对科学库导入、PDF 渲染、结构图生成、文件写入及越界访问拒绝；不创建模型 thread/turn。失败返回 `TOOL_EXECUTION_UNAVAILABLE`，不启动模型生成。只通过 `--version` 或宿主 Python 检查不能代表模型工具能工作。首次使用新配置仍需另行做小规模授权验证。

Admin Codex 使用私有 stdio app-server 桥接，模型 thread/turn 不开放为网页端口。`externalSandbox` 将文件访问限制交给已安装的外层 Landlock；启动前通过受保护探针验证隔离，禁止为了兼容而开放主机 daemon socket、其他任务目录或应用凭据。该策略不声称隔离网络：提供商请求仍需要网络。实际文件编辑与读图能力用本机 Codex＋本地合成 Responses 服务验证，不产生提供商费用；这不能替代真实论文质量评估。

Admin 科学子进程通过 Linux Landlock（ABI ≥ 3）限制文件访问：只读运行库和所需代码、仅写当前任务及临时目录；使用不含历史会话的临时模型配置目录，确认进程结束后清理。应用凭据、其他任务目录和父进程环境不在读取范围内。缺少隔离能力时拒绝执行，不降级为无限制运行。提供商网络访问仍开放；这是文件访问隔离，不是网络沙箱。

协调器随后端启动，队列、占用名额与终态由 PostgreSQL 保存。服务重启后不会自动重跑未知结果；先按 boot/PID/start ticks/session 身份检查旧进程，旧进程未确认退出时保留名额。隔离启动器通过 Linux subreaper 收拢包括自行创建 session 的后代，退出前逐个终止并回收；只有模型无法写入的清理回执确认全部后代结束，才清理临时配置并释放名额。启动器被强杀、回执缺失或身份不符时，即使主 PID 已消失仍保留名额；工具预检进程也适用。旧 boot 的进程已不存在时可按身份安全恢复。不能通过手改任务为 completed 来释放名额。操作记录和安全诊断在任务目录；不要把原始 reasoning 日志复制到网页或给非来源阅读角色。

数据库迁移需先备份并核对实例身份。Preview 的数据和运行产物不随源代码部署导入生产。测试使用独立 `_test` 数据库和合成 PDF，不会为界面验证启动真实付费任务。

## 草稿交付与检查报告

启动首次预填即授权将正常结束任务中可安全保存的候选导入当前空白草稿。Compound 覆盖缺口、来源冲突、自检未决或报告缺项不再单独阻止草稿入库；生产者仍须完成有界自检并如实记录，不为通过检查而捏造结构或把 unresolved 改成 checked。无法确定结构的身份留在完整清单与未决报告中，不创建无结构占位 Compound。

任务运行结果、草稿交付和科学审核分别记录：`needs_revision`/`partial` 保留原科学状态，`delivery_state=applied` 表示已写入待审核草稿，界面显示“已导入，待审核”。生成与自检报告在任务页可查看清单覆盖、缺失标签、七项自检及程序诊断；报告随候选 SHA256 和写入版本在数据库冻结，导入不意味着独立复核或人工批准。检查器的 blocking 指不能声明科学自检通过，不等同于禁止保存草稿。

无候选、无效结构/引用/格式、源或候选身份不符、工作区已被编辑或替换、执行取消/超时/失败/配置不符仍阻止自动写入。不能覆盖人工修改、重置工作区或篡改原运行状态来强行交付。已导入任务禁用“重试为新任务”；后续独立检查绑定已保存草稿。授权恢复历史有效结果可由受信操作者使用 `deliver_result(..., deliver_saved=True)`，它核对进程清理、无其他同篇任务、冻结身份和当前空白版本，保留旧交付诊断，不重跑模型或隐式启动付费复核。

### 交付失败后的网页恢复

若模型已经正常完成，只有数据库写入失败，任务保留生成与自检报告，并提供“重新导入已生成结果”。该按钮只重试交付，不调用模型、不追加独立复核；再次检查冻结候选、来源、进程清理和当前空白草稿。已导入时重复请求幂等返回，草稿或分配已变化则拒绝覆盖。执行失败、未生成候选或身份不明的任务不能用此按钮绕过检查。

同一 Compound、页码和裁剪框（按数据库坐标精度）重复出现时，导入层保存一份结构来源截图，所有原定位 ref 映射到同一记录，合并保留来源上下文及标签，并在报告显示“导入处理记录”。原候选不改写，不合并不同 Compound 或不同位置。数据库事务错误使用 `DELIVERY_WRITE_FAILED` 并保存安全的异常类型/约束标识；网页不返回 SQL、参数或原始异常消息，`DELIVERY_CONFLICT` 不再笼统代指每一种写入失败。

合并后的来源说明若超过候选字段长度上限，截图保留首条原始说明，完整的逐条标签和上下文保存在报告的“原始来源说明”及交付元数据；不得截断或丢弃。工作区导出仅允许经原候选验证属于同一位置的 locator aliases，选用稳定主引用并保留别名和原始说明；其他实体的多对一映射仍视为错误。

## 统计报告与轻量修补

生成和独立复核报告默认展示 Compound、Activity、Lineage、Edge、Evidence、截图数量、Compound 清单覆盖和独立复核记录覆盖。截图数量区分结构来源 occurrence、Evidence 裁图和唯一页面区域，不将重复引用冒充独立源图。生成阶段无逐项独立核验时“AI 复核支持”为未知；有 review_hint 或诊断的项显示需核对，未标记不等于可信。独立复核的支持/错误/不确定/未检查依据实际字段结论及端点依赖计算，不代表人工批准。问题按类别汇总，最多突出三项代表性问题，完整逐项记录按需展开。

启动独立复核前选择模型、推理强度和时限；该任务的一次新上下文同时完成“核查冻结草稿＋生成修补方案”，只占一个队列任务/运行名额，不再提供单独调用模型生成方案的按钮。同一会话先保存原草稿的独立审查，再基于有依据的问题和依赖生成修订候选并做有界自检；全程不修改数据库中的科学数据。页面展示原草稿审查统计，以及方案的新增、更新、删除数量和可展开的前后差异。没有可支持的修改时说明原因；修补未完成或产物无效时仍保留有效审查报告，不自动发起另一轮模型调用。

点击“接受修改”只应用已保存方案，不调用模型，也不自动排队再次复核。应用前核验方案及候选哈希、来源、草稿与分配版本、进程清理和当前同篇任务；草稿发生后续编辑则拒绝旧方案，需重新复核。仅修改实际变化的记录，保留未变记录身份、人工字段和历史；修改结构会同步派生结构/重绘，受影响的确认状态回到待核。应用记录保存接受人、复核任务及其修补方案和修改前后内容，结果仍待人工审核。

此链路为“一次独立复核（发现问题＋修补方案）→ 接受修改”。历史仅审查任务仍保留原报告，历史修补任务仍按其原契约记录；不重写旧任务包。不会自动采纳审查意见；复核可能出错，修补也可能保留未决。修补后自检提示数量不等于原复核问题已解决数量，尚未独立验证的修改不计为新一轮独立通过。

### 已完成模型任务的交付恢复

若模型进程正常退出且已确认清理，但旧版产物读取器导致复核交付失败，受信操作者可使用 `app.ai_tasks.review_recovery.recover_saved_review` 对原任务重新进行确定性校验。仅处理 `RUN_FAILED`、退出码 0 的合并复核；重新核对冻结输入、原草稿版本与内容、报告和完整修补候选。成功后恢复为方案待接受，清除网页上的失败提示，不调用模型，也不自动接受修改。

原任务包、状态文件和运行来源记录保留不变。新增的服务器校验记录保存原错误、校验时间和输入/输出哈希，并绑定到任务配置；接受方案时再次验证这份记录及原文件。正常模型退出不能替代候选校验，未完成、配置不符、文件变更或草稿已有后续编辑时不能用此方式恢复。科学未决项继续展示，恢复交付不等于科学批准。
