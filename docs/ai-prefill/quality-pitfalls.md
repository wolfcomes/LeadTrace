# 常见质量问题与验收要求

本文件是当前指南的一部分，归纳提取与审查中需要持续执行的质量规则。历史案例只用于说明失误类型；新任务复制当前文件并记录hash，既有任务包保持原样。

## 1. 交付前按表闭合，不能以 exit0 验收

提取前枚举正文每张表的列、行标签、浓度/物种/时间层级、可提取测量数量。逐表保存机器可读的测量清单，然后扩展 Activity。完成一表立刻保存候选和清单的匹配结果。

交付必须列出每张表 expected / extracted / unresolved / not_applicable，且分类理由明确。未知 expected 必须保留 unknown，不能用候选条数反推。发现整表、整列或整物种遗漏时应继续该表提取；若仍不可读，保留有源定位的缺失清单，状态为 incomplete，不能因时间预算尚充足却口头声称“time cap”而结束。

010本轮249条Activity少于旧版314条，旧31个固定源观察中5个明确缺失；其中Table4的13a遗漏甚至未在omissions列出。013本轮Table12的10µM整列遗漏。两者说明 compound 目录覆盖不能代替测量覆盖。

## 2. 表格必须同时保留中心值、误差、条件

保存原始单元格token、行身份、完整列头、中心值、SD/SEM及其类型、单位、比较符、浓度/时间/物种。抽查任一剂量列出错时，停止扩展并回查整列；另一列正确不能验证这一列。

只有数值匹配而误差或条件未查，必须记 field-level/value-only 或 uncertain。已知错误记 incorrect；源观察不在候选中记 missing。三种问题不同，不得混为“准确率”。

## 3. 立体身份不能只写进 compound_label

当源明确给定 R/S 或已知桥头构型，检查 RDKit CIP 与源指定身份；出现 `R-X`、`S-X` 两个标签却拥有相同的无立体编码图时，阻止将其记为已完成结构。不得用同一个平面图加一条 omissions 声明绕过 supervisor gate。

当源只说“分离出的更有效对映体”、没有绝对构型时，不得猜 R/S。保留真实描述和未决状态；这与源明确指定但编码遗漏的情形分别处理。必要时主结构保持 constitution-only 并明确未决，但不能计入已验证立体身份，也不能违反该轮更严格的门禁约束。

Methods 的盐型与正文展示的母体结构应分开记录。不能把所有游离碱自动判错，也不能把盐型不同的两个实验实体无条件合并。判断应以该条记录声明的化学身份为准。

## 4. 合成 lineage 的摘要边仍需真实前体关系

无文本 evidence 的 AI 推断 edge 仍允许。SAR 比较可根据实际结构与研究讨论推断；synthesis 必须说明源中从 parent 到 child 的直接反应或多步前体路径。

不能因两个终产物出现在同一文章、共享通用路线，就把它们连成“多步合成摘要”。若真实前体都是 Methods-only 节点，使用路线细节保留这些节点，或保留两个终点分支；不要为填满图而虚构终点之间的反应。010本轮 `9 → 24a` 就是已确认的错误案例。

## 5. 审查器也需要可检查的输出和来源边界

- 开始60秒内保存初始审查记录，未查项标 uncertain/blocked；每查完一项就更新。不要等全部分析完成才一次写文件。
- 固定测量探针应包含用于匹配的条件维度（例如温度），隐藏旧答案时不能一并隐藏必要的匹配条件。
- source.pdf 与 SI 分开列可用性；正文引用SI不代表已读取SI，正文Experimental也不应写成SI。Preview链未检查时不得自报 ALL MATCH。
- 审查报告内部存在相互矛盾的取代基/链长描述，应回源修正审查，不能先改候选来迎合错误审查。
- self-check “100%”不自动成为独立准确率。最终指标由保存的逐项审查记录重算，固定样本、补充样本、覆盖缺失分别统计。

## 6. 成本数据不足时不要宣称降本比例

分别记录harness调用数、超时/返工次数、各阶段耗时、监督耗时，以及实际可获得的输入/输出token和收费。预计模型名不等于实际后端模型确认。缺失的usage/cost保留null。

复跑结果支持“并行DeepSeek + 分阶段监督能发现并纠正系统错误”，还不支持“只升级提示文档就能稳定高质量交付”。下一步优先把按表覆盖、明确R/S身份冲突、审查输出持久化及门禁执行做成可运行的验收，而非继续扩大单个提示词。
