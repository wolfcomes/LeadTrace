# Article metadata implementation plan

**Goal:** Add the approved first batch of source-backed article metadata across AI candidates, editable workspace, frozen approval/publication, and a small metadata-only backfill pilot.
**Architecture:** Add optional pmid, pmcid, identifiers_source, abstract_status, abstract_note and research_profile to existing ArticleMetadata. Persist as additive Paper columns; research_profile is typed JSON with arrays. Preserve absent historical fields/hash compatibility. Manual updates are versioned and audited; existing scientific rows are never replaced. AI missing metadata is a reported gap, not forced invented content.
**Stack:** Pydantic/SQLAlchemy/PostgreSQL, Vue/TypeScript, Vitest/Playwright.

## Contract
- pmid: optional numeric string; pmcid: optional PMC plus digits; identifiers_source optional string.
- abstract_status: not_checked (default), extracted, not_found, needs_review; abstract_note optional string. Extracted requires nonblank abstract and source when delivered as full data; not_found/needs_review requires reason; PATCH validation must support updating existing fields without re-sending unrelated values, validate merged state. Legacy populated abstract without status is accepted/displayed as existing unclassified text, not invented approval.
- research_profile defaults {} with arrays molecular_forms, modalities, mechanisms, diseases, optimization_goals. Each item {label, source, review_hint?}; label/source nonblank. Target array: {name, role: primary|co_primary|selectivity|off_target|mechanistic|biomarker|unknown, organism?, gene_symbol?, uniprot_id?, ncbi_gene_id?, source, review_hint?}. Targets need not map to a gene. No inferred human species or gene mapping. JSON arrays empty vs absent preserved for old snapshots.
- controlled UI suggestions but source-supported free text labels permitted. No molecular properties duplicated from Compound.

## Work
1. Backend contract and integration: regression tests for full persistence/snapshot/publication/export/apply/repair, absent legacy hashes, invalid IDs, provenance, stale versions and partial PATCH validation. Implement additive migration0035 and model changes; central metadata fields constant; update all metadata field paths. Generate candidate schema via existing exporter. Run serial DB suites against separate disposable cluster ending _test, never production.
2. Frontend: shared Zod schema and typed entries; extend ArticleMetadata display and bibliography form with compact source-aware groups and target rows. Admin article comparison must render nested values readably and preserve change-only collapse. Add meaningful UI tests and synthetic browser coverage; full frontend tests/typecheck/build.
3. AI guidance: promote article metadata/abstract to mandatory checked scope. Missing abstract requires status/reason/omission; no made-up source or rewritten summary. Update producer/selfcheck/review/repair guides, example and deterministic gap report to detect omitted abstract without breaking legacy candidates. Do not rewrite historical bundles.
4. Pilot: use trusted bibliographic lookup by exact DOI for a few missing abstracts/PMIDs; no source PDFs read by supervisor. Save reviewable metadata-only patch proposals and identity/provenance receipt. Preserve all human edits/versions, never approve or overwrite frozen submissions. If external lookup inaccessible, report exact blocker and preserve completed work.
5. Review/test/integrate: independent spec then quality review; schema upgrade and production code rollout only after concrete release/backup/migration verification. Do not import Preview data. Deliver first version in isolated local preview if production migration not explicitly authorized; preserve worktrees. Archive completed plan with hash outside tracked tree.
