# Lead Trace 与 Dashboard 视觉统一设计

## 背景

当前 Dashboard 已形成清晰的编辑式视觉语言：深蓝固定侧栏、米白纸张背景、珊瑚红与青绿色强调色、衬线大标题、紧凑指标卡和低圆角面板。Lead Trace 的页面则更接近通用后台系统，白底、绿色主色、大圆角卡片和分散的页面级样式较多，两个入口看起来不像同一产品体系。

本次改造覆盖整个 Lead Trace，包括应用外壳、公开发布区、审核与编辑工作流以及后台管理页面。目标是高度沿用 Dashboard 的视觉语言，同时保留 Lead Trace 对复杂表单、数据表格、分子结构、PDF 审阅和权限操作所需的信息密度与可用性。

## 目标

- 让 Dashboard 和 Lead Trace 明确属于同一产品体系。
- 统一全站的颜色、字体、间距、边框、阴影、控件和页面层级。
- 保持现有路由、API、权限、筛选、分页、审核和发布行为不变。
- 集中管理样式，避免在各个 Vue 页面中重复存储基础视觉规则。
- 保持桌面端高信息密度，并为平板和移动端提供可用的响应式布局。
- 保持键盘操作、焦点状态、颜色对比度和 reduced-motion 支持。

## 视觉方向

### 色彩与材质

- 页面背景使用 Dashboard 的温暖米白纸张色。
- 主导航使用深蓝墨色背景。
- 珊瑚红用于当前导航、主要动作和重点提示。
- 青绿色用于正常、完成、确认和健康状态。
- 琥珀色用于待处理、需要注意和非阻断警告。
- 危险操作继续使用独立红色语义，不因品牌统一而降低辨识度。
- 内容面板使用细边框、低阴影和较小圆角，减少通用“大圆角悬浮卡片”观感。

### 字体与信息层级

- 页面标题、关键指标使用 Newsreader、Georgia 或兼容衬线字体。
- 正文、导航和表单使用 Manrope 与系统无衬线字体。
- DOI、Paper ID、release key、状态码和技术元数据使用等宽字体。
- 页面标题区统一采用 eyebrow、主标题、描述和上下文摘要的结构。
- 指标、列表和状态摘要使用 Dashboard 的编号、色条、细分隔线与小型 mono 标签。

## 信息架构与页面外壳

`AppShell` 作为全站统一框架：

- 左侧采用 Dashboard 风格的固定深蓝侧栏，统一品牌区、导航节奏、活动状态和底部运行状态。
- 导航继续按照当前用户角色和权限动态显示，不改变路由与鉴权逻辑。
- 顶栏使用米白半透明背景与细底边，保留发布状态、账号信息、密码修改和退出操作。
- 内容区统一最大宽度、页面边距、标题区和纵向节奏。
- 移动端将固定侧栏转换为紧凑顶部/折叠导航，确保主要操作可达。

## 集中式样式架构

样式集中管理是本次实现的硬约束。

全局样式按职责放入少量文件，并由统一入口加载：

- `tokens.css`：品牌色、语义色、字体、字号、间距、边框、圆角、阴影、层级和断点变量。
- `base.css`：reset、body、链接、标题、焦点、滚动和 reduced-motion 等基础规则。
- `components.css`：按钮、输入框、选择框、状态标签、卡片、面板、表格、分页、空状态和反馈提示等共享组件规则。
- `layouts.css`：AppShell、侧栏、顶栏、页面容器、标题区、内容网格和响应式布局。

Vue 单文件组件中的 `scoped` 样式只保留真正属于该组件的特殊布局，例如 PDF 画布叠层、分子结构对比布局或谱系关系绘制。按钮、卡片、表格、标签、输入框、页面标题和状态色不得在多个页面重复定义。若两个以上页面使用同一模式，应提升到集中样式文件或共享组件。

迁移过程中保留现有 class 的兼容层，逐页收敛后再删除重复规则，避免一次性重写模板造成行为回归。

## 页面设计

### 公开发布区

- 概览页使用 Dashboard 风格的 metric grid，强化发布版本和数据覆盖情况。
- 论文库把筛选条件组织为紧凑工具面板，结果列表采用编辑式行结构，突出标题、DOI、靶点和审核状态。
- 论文详情建立主内容与证据/状态辅助区的层级，强化谱系、结构确认、来源与发布信息。

### 审核与编辑区

- 任务、changeset、审批和冲突页面统一为“标题区—状态摘要—工作面板”的结构。
- 表单字段、动作按钮、错误提示、保存状态和只读状态采用统一组件规则。
- 化合物、结构、谱系、证据和 PDF 审阅组件保持专业工具所需空间，不强制套用首页卡片比例。
- 状态颜色表达固定：确认/完成为青绿，重点动作/当前状态为珊瑚，待处理为琥珀，错误/危险为红色。

### 后台管理区

- 统一表格表头、行分隔、hover、选中、空状态、分页和行内操作。
- 系统、任务、导入、文件、用户和审计页面共用管理页骨架。
- 危险操作保持显著的确认与危险色语义。

## 行为与数据边界

- 不修改 API、数据库模型和后端业务规则。
- 不改变路由名称、权限判断和角色可见性。
- 不删除现有筛选条件、表单字段和操作入口。
- 不改变中文文案的业务含义。
- 不复制 Dashboard 的业务代码；只提炼并复用其视觉规则。
- 保留当前工作区已有修改，对重叠文件进行兼容合并。

## 验证策略

- 先编写失败的结构测试，锁定 AppShell、导航、页面语义结构和共享 class 的预期。
- 运行现有 Vitest 测试，验证公开发布、筛选、分页、详情、审核和管理行为不变。
- 使用 Playwright 覆盖访客、审核员和管理员的主要路径。
- 检查桌面、平板和移动断点下的导航、表格、筛选器和详情布局。
- 运行类型检查与生产构建。
- 运行或扩充可访问性检查，覆盖对比度、键盘焦点、表单标签、状态提示和 reduced motion。
- 对 Dashboard 和 Lead Trace 的代表页面进行并排截图检查，确认色彩、字体、留白、面板和状态语义一致。

## 非目标

- 不重新设计业务流程。
- 不新增数据分析功能。
- 不替换现有 Vue 技术栈。
- 不在本轮引入重量级 UI 组件库。
- 不追求逐像素复制 Dashboard；复杂业务页面允许基于同一视觉语言进行适配。
