# Reviewer-style frozen record comparison implementation plan

Goal: Deliver the user-approved complete-record side-by-side Admin review with visible evidence crops and whole-Lineage comparison, preserving the existing immutable comparison API and approval semantics.
Architecture: Keep the tested scientific net-diff model; build a snapshot-only projection into article/compound/lineage records, including dependency changes. Render read-only Reviewer-style cards from frozen values. Paired lineage graphs share union node positions, selectable members/edges and synchronized viewport; source crops are rendered from frozen PDF/hash/page/bbox, never mutable source-image routes. No database/schema change expected.
Tech stack: Vue3, TypeScript, PDF.js, Cytoscape, Vitest, Playwright.

1. Write failing projection tests for full context, dependency propagation (structure/activity/shared evidence into impacted compounds/lineages), additions/deletions, no-op confirmations, stable identity, missing baseline. Implement approvals/recordComparison.ts using comparison.ts output.
2. Write UI tests for tabs, changed/all filter, record navigation, paired compound cards including structures/activity/evidence and issues; implement snapshot-only components, preserve shared i18n/tokens and collapsed full content/history. Avoid live workspace fetching or mutation.
3. Write graph tests for shared positions, added/deleted/rewired edges, evidence-only changes, shared compound impacts, selection and pan/zoom sync. Implement whole-Lineage dual graph plus paired selected relation/member details, labels and fullscreen. Only graph presentation changes; never persist reviewer layout.
4. Write crop tests for source mismatch/error/no-bbox and visible non-distorted evidence crop. Implement a lazy PDF crop viewer using frozen locator with high-DPI bounded render and enlarged region/full-page access; do not read source content as supervising agent. Synthetic fixtures only.
5. Parent owns e2e/approval-records.spec.ts: synthetic desktop/mobile, tab selection, graph synchronization, evidence screenshot default visibility, no scientific writes. Update affected legacy tests rather than hide failures. Full frontend suite/typecheck/build; synthetic PDF and Ketcher CSP regressions. Independent spec then quality review; fix findings.
6. Archive completed design/plan with hashes in ignored runtime artifacts; document current behavior. Commit and integrate verified code preserving existing unrelated root docs and ai-prefill-tools worktree. Deliver approved update with immutable release and staged frontend/CSP/hash checks, preserve old hashed assets and runtime/backend/database when frontend-only. If backend change needed, run isolated DB suites serially and backup/stage before rollout. Verify live read-only metadata, maintain no real Admin decisions. Update runtime handoffs.
